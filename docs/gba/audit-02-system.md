# Audit 02: system services vs the GBA

Scope: what np2d gives a Lua game around the PPU (saves, time, input, link, assets, math, sandbox) against what the GBA
offered, checked against code. Reference digest: `docs/gba/02-system.md` (claims re-verified below, errors listed in
section 3). Read-only audit; nothing outside `docs/gba/` was touched. Paths are relative to `np2d/`. "unverified" =
not confirmed in code or on hardware.

### Sandbox risk for big genres (item 8)

- **JRPG**: party, items, quests as tables plus `store` <= 64 KB: well inside 4 MB. Dialogue through `story`/`file()` (1 MB cap each, copied into the Lua heap). Map data as tilemaps lives outside the quota. Risk: low. Watch `_init` that `require`s many data modules (compile cost, not the instruction cap).
- **Tactics**: pathing and reach are in C (`grid`, `lua_grid.c`, `docs/lua.md:364-368`); the instruction cap is far above a frame. Main risk is frame time, not the cap: AI turn loops in Lua can take tens of ms with no yield (`perf()` is the only tool). Suggest `coroutine` spreading of AI over ticks (coroutine lib is open, `lua_game.c:1123`).
- **Cap vs frame**: 20 M instructions is roughly a second or more of console time (unverified), so the guard will not stop a 50 ms hitch.

## 2. Ranked top 8

1. **Integrity of `store`**: add CRC32 trailer + advance `store_gen` only after a successful write (1c, 1e). Smallest change that matches the GBA's checksum + counter pattern; the pieces (`crc32_buf`, A/B) already exist. Effort S.
2. **Console save window and no `fsync`**: add `fsync` before `fclose` in `save_file_atomic`, document the 1 s deferral, report task write failures back (1d). S/M.
3. **Doc and header fixes**: instruction budget 50M vs 20M (`docs/lua.md:730`), sprite size comment `ppu.h:51`, and the digest corrections of section 3. S.
4. **Document `math.randomseed` and a seeding recipe** (3c): closes the "no seed API" genre gap at zero engine cost. S.
5. **Make `btn`/`btnp` reject unknown names** and document a GBA L/R/Select mapping plus Emerald's 40/5 repeat (4a, 4b). S.
6. **Asset budget visibility**: `perf()` picture bytes / loads this frame, `preload`, and a validator resident-set report (2, 6b). M.
7. **Link envelope doc + optional `lib/lockstep.lua`** (input delay, resend, start-tick handshake); state clearly that ids are not 0..3 and the cap is 16, not 4 (5). M.
8. **Browser sync feedback** (`syncfs` errors, `pagehide` reliability) and a nil-able `date()` for web/desktop only if a game asks (1f, 3a). S-M, low priority.

## 3. Corrections to `docs/gba/02-system.md`

- Section 7: "is the existing write atomic (write temp then rename)?" Answer: no rename; it alternates two files by `#gen` parity (`lua_game.c:924-936`). Pattern is GBA-like but without the checksum.
- Section 8: "a fixed player cap of 4 (IDs 0-3) matches `link.peers()` order" is wrong: `LINK_PEERS` is 16 (`bp.h:69`) and ids are 31-bit radio-derived values (`link.c:74`), so a game must use the index in the sorted `peers()` list.
- Section 4: `seed_from_time()` is "maybe"; `math.randomseed` already exists in the sandbox (undocumented).
- Section 5/11: assets are not "probably PNG/rgb565": raw RGB565, raw indexed, raw tiles, and the packed `.pk` run format; no LZ77 and none needed.
- Section 6: pinyol has 9 Lua buttons (`start`, `c`, `menu` included), but no L/R/Select; the digest said only "C and MENU extra".
- Section 10: "`perf()` could report bytes uploaded" stands; today it reports four numbers only.

## 4. Unverified

- Whether the SD card path (versus internal flash FAT) gets saves; `hal.h:60` only mentions the flash.
- IDBFS transactionality across `v2.json` and `v2.json.b`.
- Bit-equality of 32-bit `sinf`/`cosf` between ESP32-S3, desktop and WASM (matters only for lockstep and replays).
- Wall time of 20 M VM instructions on the console.
- How often a torn in-place overwrite still parses as a valid JSON object.
