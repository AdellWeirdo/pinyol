# Audit 01: np2d video model (`src/ppu.c`) against real GBA behaviour

Scope: `src/ppu.h`, `src/ppu.c` (all 512 lines), `src/gfx_px.h` (not PPU; surface helpers only), the Lua bindings in `src/lua_game.c` (the only file that touches `PPU.*`), `docs/lua.md`, and the digest `docs/gba/01-ppu.md`. Read-only: no engine file was changed. Existing coverage: `tests/ppu_test.c` (363 lines, ~12 scene functions, pixel-level `CHECK`s, no whole-frame goldens).

Confidence: claims about np2d are from reading the code (file:line cited). Claims about hardware come from the digest and carry its confidence; "unverified" marks things I could not confirm (I did not re-fetch GBATEK; every hardware statement is as tagged in `01-ppu.md`). Nothing here was run: no binary was built, so behaviours are derived by reading, not by execution.

## 0. Two doc findings asked about

1. **Sprite size cap: `ppu.h` is stale, `lua.md` is right.** `ppu_obj.w/h` are `uint8_t` (`ppu.h:51`), `spr()` casts the sheet size to `uint8_t` (`lua_game.c:689`), and both sheet loaders reject only `> 255` (`lua_game.c:93` indexed, `lua_game.c:102` direct). So a sprite can be up to 255x255, and with `DOUBLE` the box is up to 510x510 (`ppu.c:288`). The comment "up to 128 x 128" at `ppu.h:51` should say 255. (Hardware: 64x64, double 128x128.)
2. **`PPU.line.fx_ev` is confirmed unreachable from Lua.** Only `ppu.c:461` reads it; `lua_game.c:660` only sets it to NULL; no Lua call writes it. It also encodes a simplification: `ea = ey = fx_ev[y]`, `eb = 16 - ea`, so per-line EVA/EVB/EVY cannot be set independently (hardware can).

## 1. Model summary (what np2d is, relative to the GBA)

- There is no DISPCNT mode. Each of the 4 BGs is independently `BG_TILES`, `BG_AFFINE` or `BG_BITMAP` (`ppu.h:26`), so any combination is possible (hardware: fixed mode table). `PPU.layers` is the DISPCNT enable bits.
- Composition is back to front per priority: backdrop, then for p = 3..0 the BGs of priority p (BG3 first, so BG0 on top), then the sprites of p (127 first, so 0 on top) (`ppu.c:372-381, 458`). A buffer keeps the top pixel and the one under it, each tagged with its layer id (`ppu.c:25, 92-96`). Colours are RGB565; green keeps 6 bits genuinely (`to565`, `lua_api.h:33`: `g >> 2`), so np2d is not 15-bit.
- Pixels are 1 byte indexed (index 0 transparent, `+16*bank` wrap 256) or direct RGB565 with optional 1-bit mask.

## 3. (a) Ranked "fix these first" list

Ranking weighs visibility to game makers, effort and risk to frame time. Everything below touches only the paths named; none changes the plain fast paths (`tile_run` opaque, plain indexed sprite) that the perf comments at `ppu.c:1-9` protect.

1. **Bind per-line blend/fade to Lua** (`line_blend(y, eva[, evb])`, `line_fade(y, evy)` or one table; extend `ppu.h:96` so EVA/EVB/EVY are independent). Effort S, perf low (one byte read per line already exists; `fade_tables` rebuilds 64 entries when ey changes between lines, `ppu.c:396-405`, about 160*64 steps per frame worst case, acceptable but measure on the S3). Unlocks Mode 7 distance fog, HBlank fades; the single biggest gap in `04-genres.md` section 7.
2. **Semi-transparent sprite over another sprite: keep `under` = the BG** (`put`, `ppu.c:92-96`, row 13). Effort S, perf none. Shadows and ghosts overlapping sprites currently render opaque or blend with the wrong pixel.
3. **OBJ window enabled but no `WINDOW` sprite this frame: apply `win.out`** (`ppu.c:454`, row 12a). Effort S, perf none. Flashlight/cave effects black out correctly when the light sprite is hidden.
4. **BLEND sprite ignores the window FX bit when a second target exists** (reorder `ppu.c:484-489`, row 12b). Effort S, perf none.
5. **(Done: `line_pal`, `line_pal_obj`; see 04-genres.md section 10 for what it cost.) Per-line palette overrides** (a few entries of BG/OBJ palette, applied at line start). Effort M, perf low (patch/restore a handful of entries per line; do NOT copy 160 palettes). Raster-bar skies, water bands, per-line recolours.
6. **Affine/scalable bitmap BG** (reuse the `bg_affine_x` stepping on RGB565 + mask; honour `line.affine`). Effort M, perf low (only when a matrix is set). Zooming title screens, rotozoom intros.
7. **OBJ mosaic: clamp the first partial cell into the sprite** and stop mosaicking OBJ-window shapes (`ppu.c:300-302, 345-347, 359-366`). Effort S, perf none.
8. **Per-line mosaic size and per-line layer enable/priority** (`line_mosaic`, `line_show`): small tables read in `line()`/`layers_x`. Effort S-M, perf low. Split screens, HBlank BG toggles, wipes.
9. **Window wrap (X2 < X1, Y1 > Y2) as Tonc/mGBA/NBA** (`ppu.c:440-443`). Effort S, perf none, behaviour change: games passing x1 > x2 today get nothing; ship behind a note in `lua.md` and a golden test (G15 below). Unverified on hardware (sources disagree).
10. **Optional sprite per-line budget (opt-in, cycle model of the digest)** as a maker-facing check and an ESP32 worst-case cap. Effort M, perf: cap helps, O(128) walk per line must be cached (`prepare`, `ppu.c:409`). Keep OFF by default; faithful priority hijack (row 10) stays out (L, hardware bug, no maker asks for it).

Not recommended: layer enable delay (row 26), forced blank, 8-bit memory quirks (no memory model), colour correction (post-process, digest item 40).

## 4. (b) Where pinyol is better or deliberately beyond the GBA (do not regress)

- Direct-colour sprites and direct-colour bitmap BGs with a 1-bit mask (`ppu.c:312-315, 230-281`); bitmap of any size, scrollable, wrappable, mosaic-able.
- Sprites of any size up to 255x255, DOUBLE boxes up to 510x510 (`ppu.h:51`, `ppu.c:288`); unlimited sprites per line, no flicker or dropped sprites (row 8).
- Per-BG type freedom (4 affine BGs, tiles + bitmap + affine together) and arbitrary map sizes up to 1024x1024 tiles, non-power-of-two OK, optional non-wrapping tile BGs, unbounded scroll values (`ppu.c:119-176, 213-225`).
- Per-line affine with an absolute per-line origin and `PPU_LINE_OFF` sky (`ppu.c:182-185`): no latch arithmetic, plus the `clip_span` fast path (`ppu.c:71-84, 195-212`).
- Independent window rectangles with signed coordinates and clamping; per-line window spans while keeping the vertical rule simple (`ppu.c:436-444`).
- 6-bit green throughout blends and fades (more precise than the 5-bit GBA); floors consistent with GBATEK/mGBA (`ppu.c:390-407`).
- Fade LUT cache and the "no effect can touch this line" early exit (`ppu.c:396-407, 463-479`), `ppu_tile_rows` shortcut (`ppu.c:58-69`), two-core even/odd split with separate buffers (`ppu.c:40, 499-502`), `ppu_blank` (`ppu.c:504`).
- Matrix coefficients clamped to the hardware 8.8 range (`fx8m`, `lua_game.c:~533`), 32 shared sprite matrices (`ppu.h:21`).
- Sprite pivot symmetric for even sizes (pixel-centre sampling, `ppu.c:294-298`): if it is changed to the hardware convention (row 19), do it deliberately.
- Stale `second`/`eva`/`evb` persist after `fx_off()`/`fade()`, so BLEND sprites keep blending as on hardware (BLDCNT/BLDALPHA persist regardless of mode): a Lua-visible quirk now relied upon by `BLEND` (`lua.md` Sprites table); keep.

## 5. (c) Golden-frame test scenes (lock current behaviour before changing anything)

Format: deterministic scene in `tests/ppu_golden_test.c` (same harness style as `tests/ppu_test.c`, null HAL), render 240x160 RGB565, compare CRC32 of the full frame to a recorded value AND assert the listed pixels (so a CRC change tells you something changed, and the pixel asserts say what must stay true). Use fixed-pattern generators (checker, gradient, 1-px dot) so a one-pixel shift is detectable. Render both cores' halves (the even/odd split) by calling `ppu_render` once; additionally run each scene twice to prove no state leaks (second render == first).
